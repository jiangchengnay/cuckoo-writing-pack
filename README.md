# 中文写作包（cuckoo-writing-pack）

为 [Cuckoo Code](https://github.com/wangyongpeng90/cuckoo-code) 提供一组中文写作技能，覆盖职场写作常见场景。

## 为什么需要这个插件

职场写作场景繁多（周报、技术文档、会议纪要、邮件……），每个场景都有其特定格式和规范。本插件为这些场景提供结构化的写作指南，让 AI 生成的内容更规范、更专业。

**装完即用，无需配置。** 纯提示词实现，不含任何可执行代码，启用时不会弹出安全警告。

## 包含技能

| 技能 | 触发场景 | 核心能力 |
|---|---|---|
| weekly-report | 写周报/日报 | 按成果聚合，非流水账 |
| tech-doc | 写设计文档 | 背景→目标→方案→取舍→风险 |
| readme-gen | 写 README | 自动读项目，生成安装/使用说明 |
| meeting-notes | 整理会议纪要 | 分清讨论与决议，待办明确负责人 |
| email-notify | 写邮件/通知 | 目的前置，行动明确 |
| polish-text | 润色文字 | 通顺、简洁、专业、逻辑清晰 |
| proposal | 写方案/汇报 | 结论先行，收益量化 |

## 技能详解

### weekly-report — 周报/日报/月报

把零散的工作内容整理成结构清晰的汇报。

结构：本周完成 → 进行中 → 下周计划 → 风险/求助。

规则：每条用"动词 + 对象 + 结果"；按成果聚合，不按时间罗列；数据说话；不编造未提及的工作。

### tech-doc — 技术文档

写清"为什么这么做"和"怎么做的"。

结构：背景与目标 → 现状 → 方案设计 → 方案对比 → 实现要点 → 风险与对策 → 测试与验证。

规则：先读代码/文档了解现状；用图辅助说明；术语一致；有争议的决策标注"权衡"。

### readme-gen — README 生成

为项目生成清晰、实用的 README。

结构：项目名+简介 → 特性 → 安装 → 快速开始 → 使用说明 → 配置 → FAQ → 许可。

工作方式：用 glob/read 摸清项目（语言、依赖、入口、脚本）；看现有文档/注释提取真实信息；不确定的标注"待确认"。

### meeting-notes — 会议纪要

把杂乱的会议记录整理成可执行的纪要。

结构：会议信息 → 议题与讨论 → 决议 → 待办事项（表格）→ 待定事项。

规则：分清"讨论"和"决议"；待办必须明确负责人和时间（没提就标注"待指定"）；去掉口语、重复、跑题内容。

### email-notify — 邮件/通知

写得体、清晰的工作邮件或通知。

结构：主题 → 称呼 → 正文 → 落款。

规则：目的前置；行动明确（做什么、截止时间、方式）；语气视场景调整；简洁。

### polish-text — 文案润色

在不改变原意的前提下改善文字。

方向：通顺（消除病句）→ 简洁（删冗余）→ 专业（改书面语）→ 逻辑（调整语序）。

规则：忠于原意；保留风格；标注改动原因。

### proposal — 方案/汇报

写清"为什么做、怎么做、要什么"。

结构：背景 → 目标 → 方案 → 收益 → 资源/成本 → 计划 → 风险。

规则：结论先行；收益量化；方案具体可执行；信息不足时列出假设并标注。

## 安装

### 方式一：从插件市场安装（推荐）

1. 打开 Cuckoo Code
2. 进入「插件」页面
3. 搜索 cuckoo-plugin
4. 找到「中文写作包」点击安装
5. 启用插件

### 方式二：手动克隆

    git clone https://github.com/jiangchengnay/cuckoo-writing-pack.git ~/.cuckoo/plugins/cuckoo-writing-pack

安装后在插件页启用即可。

## 特性

- **纯提示词，零执行** — 不含任何可执行代码，启用时不会弹出安全警告
- **开箱即用** — 装完即生效，无需配置
- **无外部依赖** — 不依赖任何外部服务
- **中文优化** — 每个技能都针对中文写作场景打磨

## 常见问题

**Q：和「全能技能包」有什么区别？**
A：全能技能包偏开发场景（代码审查、写测试等），本包偏写作场景（周报、文档、邮件等）。两者可同时安装，互不冲突。

**Q：技能会自动触发吗？**
A：会。当你的请求涉及相关场景时，AI 会自动引用对应技能。你也可以直接说"帮我写周报"来触发。
