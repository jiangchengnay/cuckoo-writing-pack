# 技术文档

写清"为什么这么做"和"怎么做的"。

## 结构

1. **背景与目标**：要解决什么问题，达成什么目标（可量化）。
2. **现状**：当前系统/代码是什么样。
3. **方案设计**：核心思路、关键数据结构、主要流程（可配图/伪代码）。
4. **方案对比**：备选方案 + 为什么选这个（取舍）。
5. **实现要点**：分模块说明改动点。
6. **风险与对策**：可能出问题的地方 + 应对。
7. **测试与验证**：怎么确认做对了。

## 规则

- 先读代码/文档了解现状，不凭空写。
- 用图（ASCII / mermaid）辅助说明流程和结构。
- 术语一致，首次出现的缩写给全称。
- 有争议的决策明确标注"权衡"。

## 输出

Markdown，层次清晰。关键决策用列表突出。
